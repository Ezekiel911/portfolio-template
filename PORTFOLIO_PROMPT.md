# Portfolio Site Prompt

Use this prompt when customizing or rebuilding the portfolio template:

> Customize this static portfolio for a real developer only after verified public information is supplied. Do not infer an identity, surname, age, location, education, employer, certificate, metric, testimonial, repository, outcome, or project fact.
>
> Inspect `index.html`, `js/main.js`, `js/projects.js`, `js/status.js`, `README.md`, `PORTFOLIO_SETUP_PROMPT.md`, and `PRODUCT.md` before editing. Preserve the privacy-safe starter when information is missing: use “Your Name” and a first-name-neutral monogram, keep project placeholders visible, and remove every control without a real destination. Never add direct email, a phone number, a postal address, private accounts, personal photos, biometric data, government IDs, or hidden metadata.
>
> Build the page in the Hallmark **Terminal** direction: near-black green-tinted surfaces, Martian Mono as the display and body face, one phosphor-green signal, square surfaces, hairline rules, and square primary and secondary controls. Use a meaningful monospaced hero rather than an animated CRT, glowing blobs, browser chrome, stock cards, or a hand-drawn terminal. Keep the page original and materially specific to the supplied projects.
>
> Use a settled or stage hero. At 1280 x 800, show the headline, one sentence, both actions, and the visual focal point without scrolling. The headline must be seven words or fewer, the supporting sentence twelve words or fewer, and each full section must carry more than decorative copy. Replace the generic section ladder with this portfolio anatomy:
>
> 1. Hero: name, role, project or work action, and a real visual or neutral terminal-style monogram.
> 2. Selected work: the strongest approved project, followed by the remaining projects as a filterable index.
> 3. About: a concise first-person summary and one verified goal.
> 4. Skills: a compact reference of technologies and people skills backed by project evidence.
> 5. Journey: education or experience represented as short factual rows.
> 6. Contact: only deliberately approved public links and actions.
>
> Do not use an eyebrow, tracked-caps label, pill, decorative status dot, middle-dot meta string, arrow glued to link text, metric, testimonial, logo wall, fake dashboard, card inside a card, or invented project screenshot. Preserve project filtering, project dialogs, full-size screenshots, mobile navigation, theme switching, native keyboard behavior, reduced-motion support, and the no-JavaScript baseline.
>
> Replace every placeholder in place. Use no literal Tailwind colors or framework-default palette values for custom styling. Keep existing Tailwind utility behavior but place project-specific tokens at `:root` and the `.dark` theme block. Every interactive element needs visible instant `:focus-visible` styling. Keep `html` and `body` at `overflow-x: clip`, cap the main container, and preserve image tracks with `minmax(0, 1fr)`.
>
> Before completion, run a local server and inspect 320, 768, 1280, and 1920 px widths. Verify the hero at 1280 x 800, keyboard navigation, both themes, project filters, dialogs, links, screenshot assets, browser console, network failures, reduced motion, and no-JavaScript behavior. Scan every source and asset for personal data or secrets and update setup/deployment documentation. Report each unresolved placeholder separately rather than hiding it.
